## 04 / AI选型、集成与优化

| 组件 | 选型理由 | 集成及实测 |
| --- | --- | --- |
| Qwen3-VL 4B Instruct | 同一轻量模型覆盖中文文本与公式视觉转写 | Ollama聊天接口；最终正文与错误显式处理 |
| BGE-M3 | 支持中文问题与英文原文的语义匹配 | 块向量归一化；与词项排序融合 |
| PyMuPDF / RapidOCR | 保留矢量PDF坐标，并补充无文本页OCR | 逐页提取；低置信结果过滤 |
| SQLite / 本地文件 | 便于单机复现、来源保存和任务恢复 | WAL与外键；PDF独立保存 |
| Mermaid / Plotly | 结构图及交互图表可导出、可编辑 | 按需加载；不执行任意生成程序 |

### 从运行问题选择模型

早期Qwen3思考模型在多文任务中耗尽输出预算，转用VL指令模型后完成一次跨文回答。普通文本Qwen3仍支持thinking/content分离；VL指令模型不启用不兼容的思考参数。此选择是本机可用性取舍，不是模型优劣的全面基准。

默认LLM_MODEL=qwen3-vl:4b-instruct；EMBEDDING_MODEL=bge-m3:latest。预留兼容API入口未用付费服务验证。没有LoRA训练或新基础模型成果。


## 05 / 模块一：PDF与细粒度解析

上传后保存原始PDF并计算SHA-256。解析逐页提取文本块、位置和字号信息，依据版式重排正文、识别标题与参考条目；无有效文本层的页面走OCR。内容块同时保留文献ID、页码、顺序与矩形坐标。

| 要求 | 实现方式 | 验证范围 |
| --- | --- | --- |
| 单篇 / 批量上传 | 界面逐项上传，服务端查重与任务处理 | 相同PDF重复导入自动化通过 |
| 双栏与层级结构 | 块位置与标题启发式，侧栏标签过滤 | Attention实际样例；复杂层级需校核 |
| 作者 / 机构 / 摘要 | 首页规则与机构关键词辅助提取 | 机构为启发式，不承诺完整作者机构映射 |
| 扫描页OCR | RapidOCR识别并映射回原页面坐标 | 合成扫描页通过；非官方全扫描文档验收 |
| 长书与结构 | 逐页解析，页图按需加载 | 541页、11272块，末页11块 |

### 工程控制

长PDF不一次性渲染到前端；解析与语义索引分开，未建向量时仍可关键词检索。文档处理中断后标为可重试。当前没有整本541页书籍的全量向量索引或内存峰值基准。

app/parser.py；real-document-validation.json；test_ocr_scanned_page、test_hundred_page_document。


## 06 / 模块一：内容去重与公式

### 基于内容的版本提示

完全重复用文件哈希判断；版本候选比较前100个正文块的词项集合，已有向量时使用前80块的归一化均值。相同arXiv基础编号、词项重合大于0.7，或语义相似大于0.95且词项重合大于0.35时提示。用户可保留两版或移除另一版。

实际v1/v7记录显示正文词项重合约0.812。它不是语义模型准确率；当前没有自动逐条总结版本修订的验收证据。

截图证据：artifacts/screenshots/formula-final.png

### 视觉公式闭环

从来源块裁剪原图，合并同带短块以保留分式和尾部因子，再由本地视觉模型转写LaTeX。前端显示原文、可编辑代码和数学排版；人工保存时标记已校对。表格解析可导出，但跨行合并情况仍需修正。

失败首轮遗漏V，修复后完整保留：formula-first-crop-failure.json → formula-live-validation.json。显示可渲染不等于公式语义正确。


## 07 / 模块二：混合RAG与来源锚点

### 召回与排序

用户先限定文献集合。稀疏侧使用BM25词项得分，稠密侧使用BGE-M3归一化向量点积，过滤低于0.25的语义候选。两路按排名倒数相加，避免直接混加不同尺度的原始分数。

```text
RRF(d) = sum(1 / (60 + rank_r(d)))
单篇：合并排名后选取最多8条证据
多篇：各篇正文优先，按文献分组轮转取候选
回答：来源编号 → doc_id / chunk_id / page / bbox
```

| 链路 | 输入 / 输出 | 异常行为 |
| --- | --- | --- |
| 检索 | 问题、文献ID → 正文片段和位置 | 向量不可用时关键词回退 |
| 上下文 | 外层证据编号 + 原文 + 用户问题 | 区分原论文参考编号 |
| 生成 | 仅根据证据回答，逐项附引用 | 无证据时不调用生成模型 |
| 校验 | 检查编号存在且不越界 | 错误编号结果不采纳 |
| 核对 | 点击引用 → 原PDF对应位置 | 用户核查具体论断 |

实现：app/research.py retrieve / evidence_context / answer。代表性摘要回退会明确标记representative，不冒充真实检索命中。


## 08 / 模块二：细粒度与跨篇推理

### 单篇硬件问答

问题：“Transformer的base和big模型分别使用多少块GPU，训练了多久？”实际回答给出8块P100与12小时/3.5天，来源可定位到原文页。一次复测曾错误地把“所有模型”视作未分别说明，后增加数值、单位和适用对象核对。

### 跨篇结构比较

对Transformer与BERT的比较，最初单篇候选占据过多上下文，另一篇只取到图题。按文献轮转正文后，回答覆盖Transformer自注意力结构、BERT双向编码器及预训练任务，单次完成15.34秒。尚未全面验证GPT-1/2/3参数、归一化位置和上下文窗口对比。

| 问题类别 | 防护 / 优化 | 仍需注意 |
| --- | --- | --- |
| 比较对象漂移 | Prompt锁定用户指定对象 | 模型仍可能概括不充分 |
| 数值条件误读 | 逐项提取与共同条件复核 | 单次成功不是通用准确率 |
| 引文混用 | 原论文编号转为说明，外层编号用于回答 | 编号校验不等同逻辑蕴含验证 |
| 推理或正文截断 | 检查done_reason，拒绝不完整结果 | 模型与上下文长度仍影响可用性 |

证据：final-agent-answer.json、numeric-answer-validation.json、multi-paper-balanced-validation.json；早期失败文件保留。


## 09 / Agent工具调用与约束

用户任务 → 原生工具规划 → 白名单 / 参数检查 → 执行并收集证据 → 生成 / 引用校验

| 工具 | 开放条件 | 结果如何使用 |
| --- | --- | --- |
| search_library | 论文问题默认建议调用 | 模型建议检索词，服务端限定文献范围 |
| citation_graph | 问题涉及引用关系时可建议 | 读取真实节点与边作为补充上下文 |
| search_arxiv | 问题明确涉及新论文/外部检索 | 只返回发现元数据，不冒充阅读全文 |

工具描述和JSON参数结构通过原生Function Calling接口传入。服务端最多处理三条建议，拒绝未知工具，截断过长参数。规划失败回退固定检索，而不是无限重试。已录制的一次问答提出1个工具调用，并获取8条原文证据。

### Guardrails与数据边界

论文文本是待分析数据，不作为系统命令。引用编号检查、输出截断检查、受限远程导入和浏览器来源检查共同限制错误影响。当前不执行模型生成的任意Python；图表Python代码作为可下载成果提供。

app/llm.py plan_tools；app/research.py answer；artifacts/final-agent-answer.json。当前是单Agent有界工作流，不宣称Multi-Agent协作。

## 11 / 模块四：发现、追踪与推荐

使用公开arXiv接口按主题或标题检索，用户选择结果后下载入库。合法arXiv编号经校验后构造下载地址，拒绝任意远程URL。当前不是对整份参考文献列表逐项自主下钻的完整代理。

| 环节 | 实际机制 |
| --- | --- |
| 周期与恢复 | 持久化主题和next_run；每30秒检查；服务重启后补查 |
| 结果去重 | topic与arXiv ID组成唯一键，更新未读收件箱 |
| 失败退避 | 保留错误信息，将下次执行推迟15分钟 |
| 个性化反馈 | 本地关键词相关度，喜欢/不喜欢反馈 |
| 代码线索 | 从摘要识别GitHub链接或代码表述，附推荐理由 |

### 真实运行与可解释性

一个研究主题实际取回12条结果。推荐理由说明与本地库的相关线索，代码信息只表示摘要中提及，并不代表仓库已运行复现。当前推荐是单个本地工作空间，尚未实现多用户协同过滤。

app/tracking.py、main.py discover；tracking-live-validation.json。引用质量过滤中的“应付式引用”自动判断未实现，不把关键词相关度包装成引用质量结论。

## 17 / 创新点、总结与改进计划

### 技术与应用贡献

一是把来源块贯穿解析、问答、翻译、公式和写作；二是在多篇RAG中均衡正文候选，并保留从错误到修复的可审查证据；三是在个人电脑上组合文本与视觉模型、周期发现、图谱和可导出的科研成果。以上为工程与应用集成贡献，不宣称提出新的基础算法。

| 差距 | 改进路径与验收目标 |
| --- | --- |
| 自主探索深度 | 增加有界多轮规划与参考列表下钻；记录成功率和失败恢复 |
| 学术事实核验 | 加入论断与证据蕴含评估；扩充数值/模型演进问题集 |
