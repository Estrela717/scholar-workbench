# 真实开发记录

## 2026-11-14 / 阶段 01：需求与环境

用户原始要求：从零开始，同时参加 AI 创新应用挑战赛和 AI 大模型创新应用挑战赛，委托助手完成开发，询问今天能否完成。随后确认没有模型 API 和服务器，先做本地可运行版。

约束：两项共用科研助手产品；本地运行；所有未验证能力必须明确说明；不虚构开发过程、测试结果或用户身份。当前会话原始对话由用户在 Codex 中保留，此文件只是过程摘要，不能替代赛道要求的原始 Prompt 导出或录屏。

环境实测：Windows、Python 3.13、Node 24、32GB 内存、RTX 5060 Laptop 8GB；本地已有 Ollama、deepseek-r1:8b、deepseek-r1:14b、bge-m3:latest。新项目采用独立虚拟环境，不改动已有比赛项目。

方案：Python/FastAPI + SQLite + PyMuPDF/RapidOCR + 本地 Ollama；浏览器工作台。先建立可追踪文档数据与证据锚点，再完成问答、阅读、发现、图谱、写作。

记录规则：每次功能实现和修复都追加真实改动与检查结果；按阶段提交 Git；另保存可复现的输入与测试日志。不回填或伪造过往的交互。

## 2026-11-14 / 阶段 02：服务、界面与真实数据

实现 FastAPI / SQLite 后端与七个工作台页面，以页码和坐标为统一证据数据。用公开 Attention、BERT、RAG 论文实测导入、索引与引用，三篇建立 1,397 个语义向量。界面支持桌面与手机，CSV 上传绘图接入真实后端。

作者官网公开的 Understanding Deep Learning 版本验证了 541 页、11,272 个内容块、末页 11 块。导入 Attention v7，与 v1 获得约 0.812 正文重合度提示，没有将有限样例描述为大规模评测。

## 2026-11-14 / 阶段 03：从实际失败推进修复

- 标题误识别：arXiv 竖排侧栏干扰字号启发式，增加竖排标签排除与标题行合并。
- 引用条目被分割：按编号跨块重组并重新匹配，最终样例库有 5 条匹配边。
- 写作校验失败：首次真实写作混用了原论文编号与外层证据编号。增加编号区分，保留失败记录，修复后复测。
- Qwen 非思考模式出现无标签推理文本：启用推理分离，只读取最终正文，长度截断时报错。真实问答、翻译和写作随后均成功。
- 原生工具规划预算不足：提高 token 预算并启用 Qwen 推理分离，实测返回 search_library 工具调用和英文检索词。
- 阅读器异步切页与翻译：增加请求有效性保护和内容块 ID 对齐；问答保留在当前浏览器会话中，便于引用跳转返回。
- 全文翻译取消竞态：只允许 queued 状态领取任务，避免已取消任务被重启；覆盖缓存续传，不重复翻译已完成块。

## 2026-11-14 / 阶段 04：验收与材料

后端从 14 项扩展至 18 项测试并全部通过。新增翻译取消、缓存续传、结构提取与 BibTeX、Qwen 最终正文与截断检查。浏览器检查七个页面无运行错误，390px 宽度无横向溢出。

默认 Qwen3 4B 真实测试：问答约 57.27s（此轮规划未发出工具，回退固定检索），翻译约 21.73s，写作约 48.49s。随后修复规划预算，原生 search_library 调用约 22.38s。这些是单次本机记录，不是性能基准。

两套 10 页技术 PDF 分别强调 AI 协同过程与模型工程。视频采用实际浏览器操作和真实记录复盘，标注合成配音；不伪造用户 Prompt 或当时实时开发画面。公开对话节选仅接纳用户消息及已标记公开的助手消息，过滤内部推理与元数据。

最终生产地址检查发现 Windows 注册表将 JavaScript 标记为 text/plain，导致模块无法加载。后端显式设置 JavaScript/CSS MIME，补齐站点图标，并将浏览器检查扩展至控制台错误。修复后在 http://127.0.0.1:8765 的七个界面、CSV 与手机检查全部通过。录制中的真实智能体问答已返回 1 个原生工具建议、8 条证据和有效引用，保存为 artifacts/recorded-agent-answer.json。
